# 写作方法 · [English](writing-method.md)

本页汇总 paper_workbench 的规则所支持的“一致、连贯”的写作方法，并为每一步标出对应规则，新的论文项目可以用一段配置整体启用。
方法来自真实稿件的多轮修改，但不含这些稿件的任何文字或结果。

由作者决定。下面每条规则只是标出一个句子或一个图表；作者改写它、写明理由接受它，或修改规则（`AGENTS.md` 第 1 节）。

## 启用

把下面内容写进论文项目的 `rules.local.json`。方法中默认关闭的规则都已列出，按期刊或作者的要求删去不需要的行。数值以期刊的作者指南为准。

```jsonc
{
  "enable": ["W20", "E6", "E7", "J1",          // 摘要：结构、数字个数、数字角色、长度
             "W21", "O3",                      // 段落：旧信息在前、正文自成一体
             "W22", "W23",                     // 句子：肯定式表述、句长
             "T11", "T12", "T13"],             // 图表：图注长度、页面位置、选例说明
  "document": {
    "J1":  {"min": 150, "max": 250},
    "E6":  {"max_numbers": 2},
    "T11": {"min": 15, "max": 35},
    "T12": {"pages_after": 1}
  },
  "tone": {"W23": {"max_words": 25}}
}
```

`T12` 读取编译出的 PDF：在 `paper_workbench.json` 中设置 `"pdf": "main.pdf"`（默认依次取工作台的 PDF、`main.tex` 旁的 `main.pdf`），需要 PyMuPDF。

## 1. 从摘要到结论的一条主线

| 步骤 | 做法 | 规则 |
|---|---|---|
| 顺序 | 摘要从旧到新：领域现状、不足、动机、提出、机制、作用、结果。 | `W1`（人工） |
| 结构 | 用一句提出方法（“We propose …”），机制按 First、Second、Third 列出，其后用一句说明方法提供什么。 | `W20` |
| 数字 | 摘要只写少数数字，且各有角色：一个说明整体能力，一个说明某项具体能力，均写成相对第二名的领先幅度。 | `E6`、`E7`（人工） |
| 呼应 | 引言展开摘要的每一句，结论逐一回答且不引入新主张。 | `W4`（人工），审阅页的 **Flow** 视图 |

把摘要交给作者之前，先运行 `check --only W20,J1,E6`。连自己的结构规则都不过的提案会白费一轮。

## 2. 句与句的衔接

| 步骤 | 做法 | 规则 |
|---|---|---|
| 旧信息在前 | 句首是读者从上一句已知的内容，句末落在新信息上。 | `W21`，**old→new** 标记 |
| 主题链 | 主语承接上一句的谓语或宾语（线性），或重复上一句的主语（恒定）。连续的新主语读起来像清单。 | **topic** 标记 |
| 逻辑关系 | 连接词标示真实的关系。结果连接词只出现一次，且不用在“we propose”之前。 | `W13`、`M2`（人工），**relation** 标记 |
| 节奏 | 连续三句开头相同、长度相近，读起来平。 | **rhythm** 标记 |

`W21` 只标出明确的情况：没有共有的词、没有回指词、没有连接词，且主语是新的。审阅页在每个句子下显示全部四种标记，并给出每段的汇总（[review.zh-CN.md](review.zh-CN.md)）。单独读一段中每句的前三个词：它们应当能讲出这段的故事。

## 3. 平实的句子

句子规则按约 80% 的严格度改编自 ASD-STE100（见 `CREDITS.md`）。

| 步骤 | 做法 | 规则 |
|---|---|---|
| 一句一意 | 每句一个主要动作，从句完整，不在句末逗号后追加限定成分。 | `W14`、`W15`、`W16` |
| 句长 | 每句至多 25 个词（上限在 `W23.max_words` 中设定）。 | `W23` |
| 主动语态 | 动作的发出者作主语；“We”只用在作者是行为者的地方。 | `W10`、`W12` |
| 条件在前 | 条件先于动作。 | `W11` |
| 一词一义 | 一个概念只用一个术语、一个中心名词。先改术语表，再改正文、图和图注。 | `A3`、`A6`、`A7` |
| 平实用词 | 直接的动词，不写废话，用确切的数值代替含糊的词。 | `M1`（人工）、`W7` |

## 4. 肯定式表述

写论文做了什么、表明了什么。不要预先回应假想的质疑。

| 步骤 | 做法 | 规则 |
|---|---|---|
| 不预先让步 | 删去“we do not claim”“admittedly”“merely”“serves only as”，直接陈述事实。 | `W22` |
| 惯例 | 领域惯例（指标集、测试协议）直接陈述并给出出处，它不是本文的弱点。 | `W22`（人工判断） |
| 先写优势 | 自我批评放在局限章节，由论文在那里权衡。 | `W8`、`W9` |
| 真实代价保留 | 测得的权衡是结果，连同数值如实报告。 | — |

肯定式表述不得超出证据。若会超出，改用中性的事实句或删去该句。测得的负面结果保留在论文中。

## 5. 由正文带出的图表

| 步骤 | 做法 | 规则 |
|---|---|---|
| 图注长度 | 图注 15 至 35 个词（按你的上下限）：说明图表展示什么、怎样读；机制留在正文。 | `T9`（人工）、`T11` |
| 先引用 | 正文先引用图表，源文件中如此，页面上也如此：同页或下一页。 | `T1`、`T2`、`T12` |
| 选例 | 展示所选案例的图用几个词说明如何选出；只展示现象，不把具名方法呈现为更差。 | `T13`（人工） |
| 正文自成一体 | 正文句子不指向补充材料；主张在提出之处就有依据。 | `O3` |
| 图件 | 统一的视觉语言、可读的字号、可印刷的文件。 | `G1`–`G9` |

## 6. 修改循环

1. 每次修改写入新的版本目录，不改已交付的版本。
2. 运行 `check`，从规则树中最高的未通过层开始改。
3. 构建工作台和审阅页，阅读 Flow 视图和每个改动段落的衔接标记。
4. 记录每处改动、作者的原话以及每个数字的依据。
5. 提案交给作者之前，先对提案本身运行规则。

## 7. 可比较的审稿轮次

模拟审稿只有在各轮可比时才有用。

- **每轮设置相同。** 同一模型、同一推理强度、同一提示词；两轮之间只改提示词里的版本名。设置若有变化，在分数记录中标明，不跨变化求平均。
- **隔离的材料包。** 审稿者只拿到放在空目录里的 PDF 及其页面图像，不读源文件、笔记或以往的审稿意见。
- **全新上下文。** 每一轮都不带以往轮次的记忆。`tools/review_fresh.sh` 为 Codex CLI 实现了这一点。
- **审计。** 检查原始日志：审稿者运行的命令、读取的文件，以及材料包未被改动。
- **不追分数。** 每条意见都是一个问题。改正属实之处，直陈惯例，让每个主张不超出其证据。
